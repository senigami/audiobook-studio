6Buttons

All button variants inherit the shared button{} base (padding, radius, inline-flex, font, transition); each .btn-* only layers color, border, shadow and motion.

(a) Variants at rest

.btn-primary · .btn-success · .btn-glass · .btn-ghost · .btn-home · .btn-home.primary · .btn-danger — all inherit the base button{} rule

(b) States row

default / hover (shown statically — the :hover background + 1px lift + shadow is baked in here so you can see it; the rest-state buttons are also live-hoverable) / :disabled / loading (real app uses a lucide Loader2 + .animate-spin; shown here with .sg-spinner)

(c) Icon + label buttons

Real lucide icons (Play · Plus · Download · Trash2 · BookOpen) before the label — they inherit the button's text color via currentColor. The base button{} is inline-flex with gap:8px, so icon + label stay centered. In the live app these collapse to a 40×40 icon-only square below 1100px via .btn-responsive.

(d) Dropdown menu items

.action-menu-item.standard (hover → accent-glow + accent text) and .action-menu-item.destructive / .btn-menu-destructive (hover → error-glow + error text) inside a .popover-panel. Layout padding/flex come from per-instance inline styles in the menu component; only color/hover/focus live in the stylesheet. Both are live-hoverable.

14Toasts & inline notifications

There is no toast library. The app has exactly one transient toast — a centered bottom pill in App.tsx (inline-styled, auto-dismiss 4s, optional action button) — and most success is communicated inline ("Saved", "Copied!").

Toast — message only

Chapter saved
App.tsx toast — inline-styled pill on --as-ink, --text-on-accent text, --shadow-lg, --glass-border. Auto-dismisses after 4s. Mounted via framer-motion (slide+scale up from y:20).

Toast — with action

Project deleted
Toast with optional action — action button on --accent / --text-on-accent. Clicking runs the action then clears the toast.

Inline success affordances

Saved
Inline success — buttons swap their own label to "Saved" / "Copied!" for ~1.5s instead of firing a toast. The success-text checkmark pattern is reconstructed here (no shared class exists).
Accessibility: the toast is announced through an always-mounted visually-hidden aria-live="polite" aria-atomic="true" region in App.tsx (the visible motion pill is separate). The screen-reader span uses the classic clip: rect(0 0 0 0) off-screen technique. There is no notification stack/queue — a new toast replaces the current one.

24Voice, tone & iconography

The copy rules that keep UI text consistent — casing, CTA shape, destructive messaging, loading/success patterns, product name — and the single icon system.

Copy rules (voice-tone.md)

Casing Title Case for buttons, CTAs & modal titles ("New Project", "Delete Chapter"); sentence case everywhere else — body, empty states, loading, error, helper text.
CTAs Verb-first, action-specific. Prefer "Delete project" / "Yes, Rebuild It" over "OK" / "Confirm". Generic "OK" only on info-only alert dialogs.
In-progress buttons Swap the label to a gerund: "Create Voice" → "Creating…", "Save Changes" → "Saving…", "Rebuild Voice Model" → "Rebuilding…". Pair with a Loader2 animate-spin icon where space allows.
Destructive Any permanent delete MUST state irreversibility — "This cannot be undone." / "This action cannot be undone." in the dialog body.
Loading copy Gerund phrase + single Unicode ellipsis … (U+2026), never ...: "Loading…", "Saving…", "Checking server status…". Never a bare unlabeled spinner.
Empty states A label naming what's absent + a next-step sentence: "No chapters yet. Add one to get started." Never dead-end "Nothing here".
Error copy State the cause and the remedy: "Failed to load engines. Ensure the TTS Server is running if enabled." Never bare "Something went wrong".
Success Inline only — there is no toast system. Transient label swap ("Saving…" → "Save"), short-lived inline badge ("Copied!"), or persistent "Saved" state. Do not add a toast library.
Optional fields Append " (Optional)" to the label ("Series (Optional)"), not a bare placeholder="Optional".
Punctuation No trailing punctuation on button labels / modal titles. End body statements with a period; inline success badges may use "!" ("Copied!").
Product name "Audiobook Studio" (two words, both capitalised); short form "Studio". The repo name "audiobook-factory" is never user-facing.

Iconography (design-system.md §9)

Icons A single system: lucide-react. Every functional or decorative icon renders as a lucide component. Unicode glyphs (▶ ⏸ ▾ ▲ ▼ › ✓ ✗) and emoji (🌙 ☀️) are banned as icons — they don't inherit currentColor/stroke/optical sizing and drift between platforms.
Exceptions Status dots (a colored fill, not an icon), raster artwork (logo.png, voice avatars, engine logos), and "from → to" notation (184 → 186) are deliberately not lucide.
