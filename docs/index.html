The 2.0 rearchitecture

What's new in 2.0

Studio 2.0 moves synthesis into a managed, crash-isolated TTS Server and opens up engines and voices as installable, shareable bundles.

🧩

Managed TTS Server

Engines run in a separate process managed by Studio. An engine can crash without taking your project or queue down with it.

🎭

Per-character voices, mixed engines

Assign a different voice to each character. A single chapter can mix local XTTS voices with optional cloud voices at the segment level.

⬇️

Install engines like Stable Diffusion

Browse a tag, clone a repo, and the engine is installed. XTTS is the local default; cloud engines are opt-in.

Planned for 2.0
🎙️

A real voice library

Voices carry an icon, a playable sample, a description, and rich tags. Browse, download, and share them as portable bundles.

Planned for 2.0
🤖

AI voice casting

Describe a character and get matched to a voice from your library, with a reason for every pick. You keep final say.

Planned for 2.0
🔒

Local-first and private

Your manuscript, samples, and output stay on your machine. Anything that leaves is explicit, opt-in, and clearly disclosed.

🔌

TTS gateway API

Use Studio as a local text-to-speech backend over HTTP for your own scripts and apps, through the engines you have installed.

📦

Plugin SDK

Five methods and a manifest file let anyone wrap a new engine and share it. Built-in engines use the same contract.

♻️

Queue and recovery

Progress is reliable, unchanged audio gets reused, and work recovers cleanly after a restart.
