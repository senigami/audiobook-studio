# Implementation Map — Chapter Editor Catalog Completion

## Big picture

Every item here is an addition to the already-shipped Director's Console (`frontend/src/pages/ChapterEditor/components/DirectorsConsole/`). Nothing here is a rewrite. The design is fully agreed (`design-docs/workflows/chapter-editor-modes.md`); the work is translating an agreed design into code across four rendering surfaces (Cast's `ScriptView.tsx`, Booth's per-segment list, Revise's segment editor, and the shared `DirectorsConsole/index.tsx` shell) plus one backend endpoint (Revise's split).

## Connections — the sequencing dependency (read before starting any Cast task)

- **A (mutation-batching) blocks nothing structurally, but B and C both call the assignment API directly today** (`handleScriptAssign`/`handleScriptAssignRange` in `useChapterAssignments.ts`, one immediate awaited call per event). If B/C are built against today's immediate-write path and A lands later, both need rewiring to route through the collector instead. **Build A first**, or at minimum design B/C's event-emission to already target a collector interface from day one even if A's queue isn't finished — do not have two generations of "how does an assignment get saved" in flight.
- **A is also the fix for a known 409-conflict bug class (bug B2 per the design doc)** — it is not purely additive UX polish, it closes a real correctness gap. Treat it as load-bearing, not optional-if-time-permits.
- **F (gutter component) is shared infrastructure for E (Cast's Stage/Cue glyphs) and G (Booth's annotation glyphs).** Build F once as a standalone component before either E or G's glyph-rendering pieces, so Cast and Booth don't grow two incompatible gutter implementations. This is the single highest-value de-duplication opportunity in this plan.
- **E (data model) must land before F can render anything real** — F's glyphs need `render:false`/`engine_directives` to exist on the segment type first. Sequence: E's schema/type changes → F's shared gutter component → E's remaining render-pipeline skip logic can proceed in parallel with F once the type exists.
- **H (backend split endpoint) must land before I (frontend wiring)** — I is a small change (call the new endpoint instead of discarding the computed split) once H exists; do not build I speculatively against a nonexistent endpoint.
- **J and K are coupled** — K's Ambient status needs the render-progress state J's mode-exit tracking (and the pre-existing progress state currently trapped in `CastToolBody`) lifted to the console-shell level. Building K without J's state-lifting means inventing a second, disconnected progress source.
- **L touches three rendering surfaces** (`ScriptView.tsx` for Cast, Booth's and Revise's existing per-item tabIndex) — build the shared hook first, then apply to each surface as three small, independent follow-on tasks, so a bug in the hook is fixed once, not three times.
- **M (legacy retirement) depends on nothing else here structurally**, but deleting `ScriptView.tsx`'s per-span dropdown affects the NEW `CastTool` too (shared file) — confirm the legacy `ChapterEditor`/`EditorTabs` path is truly dead (reachability check) before removing the dropdown, since `CastTool` still uses `ScriptView.tsx`.

## Invariants

- **INV-1 — No second data model.** Variation (D) reuses `SpeakerProfile.variant_name`; brush-size word-granularity (B) reuses the existing `_split_segment_at_offset` primitive. Never invent a parallel field/table for something the app already models.
- **INV-2 — XTTS silently no-ops on SSML it can't use.** Stage Direction/Performance Cue (E) payloads must not break or visibly fail on engines that can't consume them (per the design doc's explicit "XTTS ignores the payload silently" rule).
- **INV-3 — One gutter, not two.** Cast's and Booth's annotation/cue glyphs render through the same shared component (F) — a second, incompatible gutter implementation in either mode is a map violation.
- **INV-4 — Roving tabindex, never per-item tab-stops.** Any keyboard-accessibility work (L) must not reintroduce or leave in place a "N tab-stops for N items" pattern anywhere in Cast/Booth/Revise — replace, don't add alongside.
- **INV-5 — No capability regression.** The base paint-assignment UI (already shipped), Booth's karaoke highlight + regenerate-segment, Revise's inline edit, and Write mode's full-source editor must all continue working exactly as today throughout every task in this plan.

## Risks & open questions

- **R-A — Stage Direction/Performance Cue (E) is the largest single item and touches backend schema + render pipeline, not just frontend.** It should be its own multi-task workload, not bundled with the palette-only additions (B/C/D), which are additive UI layers over already-existing data plumbing and carry much less risk.
- **R-B — The A11y keyboard model (L) replaces existing behavior in Booth/Revise, not just adds to Cast.** Removing the per-item `tabIndex={0}` pattern from two already-shipped modes is itself a real, testable regression risk — budget for full re-verification of Booth/Revise keyboard interaction, not just Cast's new composite widget.
- **R-C — Render-on-mode-exit (J) has zero existing runtime hook to attach to** — the `onModeExit` type field is declared but never called anywhere in `DirectorsConsole/index.tsx`'s mode-switch handlers. This is greenfield console-shell architecture work, not a small wiring task.
- **R-D — Legacy retirement (M)'s reachability is genuinely uncertain** — `ProjectDetailPage.tsx`'s `editingChapterId` branch depends on a server-driven `shellState.navigation.activeChapterId` field whose actual reachability from any current UI entry point needs confirming (a live click-through check, not just a code read) before deleting anything.
- **R-E — The demo mockup (`frontend/src/demo/stages/siteMockup/panes/directorsConsole.tsx`) already prototypes most of the Cast catalog (brush types, variation types, a CueEditor) in fake in-memory state** — useful as a visual/interaction reference, but it has **no eyedropper/Match Voice tool at all**, and per this repo's own convention (`00_execution_contract.md`), the mock is layout truth, not code truth — do not copy its JSX, rebuild with real components/data.
