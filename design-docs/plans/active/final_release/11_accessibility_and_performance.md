# 11 — Accessibility & Performance

Code-verified findings from a 2026-06-10 audit of `frontend/src`. Each item: file:line, problem, fix, acceptance. A11y items A1–A3 + A9 are release blockers (WCAG 2.2 AA). Coordinate modal/focus work with doc 10 (U2/Q2) — do each fix once.

## Accessibility

- [x] **A1 (Critical). ConfirmModal has no dialog semantics or focus management** — Fixed 2026-06-11. `role="dialog" aria-modal="true" aria-labelledby="confirm-modal-title"` added; `useFocusTrap` hook applied (focuses first control on open, traps Tab, restores trigger focus on close); Escape calls onCancel. Same applied to ResyncPreviewModal.
- [x] **A2 (Critical). Drawer same gaps + mouse-only resize** — Fixed 2026-06-11. `role="dialog" aria-modal` + `useFocusTrap` applied to `VoiceUtils.tsx` Drawer; `aria-label="Close"` on X button; resize handle gains `role="separator" aria-orientation="vertical" aria-valuenow/min/max tabIndex={0}` + ArrowLeft/ArrowRight keyboard handlers.
- [x] **A3 (Critical). Nav buttons lose accessible name below 1100px** — Fixed 2026-06-11. `aria-label={item.label}` added unconditionally to each nav button in `Layout.tsx`.
- [ ] **A4 (High). Icon-only buttons rely on `title` or nothing** — `ConfirmModal.tsx:92-103`, `VoiceUtils.tsx:142`, `components/queue/ReorderableQueueItem.tsx:90-108` (Trash2), `pages/ChapterEditor/components/ScriptView.tsx:427-453` (Play/Generate). Add `aria-label` to all.
- [ ] **A5 (High). Drag-reorder has no keyboard path** — `ReorderableQueueItem.tsx:70-82`. Grip gets `tabIndex={0} role="button" aria-label` + ArrowUp/ArrowDown move handlers (or explicit move-up/down buttons).
- [ ] **A6 (High). No live regions** — toast container `app/App.tsx:388-437` gets `role="status" aria-live="polite" aria-atomic="true"` (container always mounted, message conditional); add a visually-hidden polite region announcing job/chapter completion.
- [ ] **A7 (High). JsonSchemaForm labels not associated** — `pages/Settings/components/JsonSchemaForm.tsx:81-180`. Stable `id={`setting-${key}`}` + `htmlFor` per field; `aria-valuetext` on range inputs.
- [ ] **A8 (Medium). StatusOrb** — `components/ui/StatusOrb.tsx:101-103`: `aria-label` on a plain div is ignored by most AT; change to `role="img"`.
- [x] **A9 (Critical-adjacent). Global `outline: none` with no `:focus-visible` replacement** — Fixed 2026-06-11. `base.css` button `outline: none` replaced with `:not(:focus-visible)` scoped rule + universal `:focus-visible` ring (`2px solid var(--accent)`, offset 2px) for button/input/select/textarea/a/[tabindex]. Bare `outline: none` instances removed from components.css classes (`.action-menu-item`, `.input-field`, `.select-glass`, `.form-input`, `.input-group input/textarea`).
- [ ] **A10 (Medium). Landmarks/headings** — `Layout.tsx:89` nav gets `aria-label="Main navigation"`; every route gets an `<h1>` (visually-hidden acceptable) — pages currently start at h2/h3.
- [ ] **A11 (Medium). `--text-muted` contrast** — `theme/tokens.css:22,25`: #64748b is ~4.1:1 on `--surface-alt` (#f1f5f9), failing AA. Darken to ~#5a6a7e or restrict to large text. Re-check after the dark palette lands (doc 07).
- [ ] **A12 (Low). `prefers-reduced-motion`** — no handling across 18 framer-motion sites. Add the global reduce-motion CSS override in `base.css` plus `useReducedMotion()` where springs are central (modals, drawer).

*A11y acceptance gate:* axe scan clean on Library, Project, Chapter Editor, Voices, Settings, Queue drawer in both themes; full keyboard walkthrough (doc 10 verification) passes with visible focus throughout.

## Performance

- [x] **P1 (High). LiveOutputTable re-renders on every websocket frame** — Fixed 2026-06-11. Added `subscribeThrottled` export to `liveEventAuditStore.ts`: in real browsers it gates listener calls via `requestAnimationFrame` so a frame burst coalesces to one render per frame; in jsdom it falls back to synchronous calls so tests need no changes. `LiveOutputTable` now uses `subscribeThrottled` instead of `subscribeLiveEventAudit`. Pinning test: `liveEventAuditStore.perf.test.ts`.
- [x] **P2 (High). Audit store allocation churn** — Fixed 2026-06-11. Ring buffer cap reduced from 1000 → 200 entries in `liveEventAuditStore.ts`; `notify()` kept synchronous so `useSyncExternalStore` works correctly. Pinning tests: `liveEventAuditStore.perf.test.ts` (cap + FIFO eviction). *(Gating question: should audit store run outside the dev page? Deferred to doc 06 runtimeDebug retirement.)*
- [x] **P3 (High). ScriptView re-renders every span per progress tick** — Fixed 2026-06-11. Extracted `ScriptSpanItem` as a `React.memo`'d component above `ScriptView` in `ScriptView.tsx`; all per-span state passed as flat primitive/stable props so React's shallow comparison bails out on unrelated progress frames. Pinning test: `ScriptSpanMemo.test.tsx`.
- [x] **P4 (Medium). Audio element leaks** — Fixed 2026-06-11. `stopPlayback` in `useChapterPlayback.ts` now nulls `onplay`, `onended`, and `onerror` in addition to `onpause`, `ontimeupdate`, `onloadedmetadata`. Pinning test: `useChapterPlayback.handlerLeak.test.tsx`.
- [x] **P5 (Medium). 250ms poll regardless of visibility** — Fixed 2026-06-11. `LiveOutputPage.tsx` replaced `setInterval(syncTrace, 250)` with `subscribeLiveEventAudit(syncTrace)` + a `visibilitychange` gate so background-tab updates are skipped.
- [x] **P6 (Medium). Duplicate 1s clocks** — Fixed 2026-06-11. New `hooks/useNow.ts` implements a ref-counted shared interval: N mounted components share exactly one `setInterval(tick, 1000)`. `QueueStats` updated to use `useNow()`. Pinning test: `useNow.test.ts` (1 interval for 3 mounts; cleared when last unmounts).
- [x] **P7 (Medium). Interval hygiene in useQueueSync** — `hooks/useQueueSync.ts:154-157`: verify the interval effect has a minimal stable dep array; connection-state thrash must not overlap intervals. (Related to doc 09 F3/F4 races — fix together.)
- [x] **P8 (Low). Bundle chunking** — `frontend/vite.config.ts`: add `manualChunks` separating `framer-motion` (~90KB) and react vendor chunks.
- [x] **P10 (Spike). Model warm-holding between renders.** (Owner request, 2026-06-11.) Reloading the TTS model for every render (e.g. regenerate after a completed job) costs the full model-load time even though batch jobs prove the engine can reuse a loaded model across segments. The TTS Server is already a long-lived subprocess, so this is a plugin-level lifecycle question, not an architecture change. Spike scope: (1) audit what XTTS does today after a job completes — does the plugin unload the model or does it stay resident; (2) if it unloads, prototype a `keep_model_loaded` plugin setting (manifest/settings-schema driven) that keeps the model resident between jobs; (3) measure memory cost and make the setting opt-in/memory-aware so only machines with headroom enable it; (4) report findings before implementation. No rewrite in a compiled language is anticipated.
- [x] **P9 (Low). `/api/home` mega-payload refetched on every reconnect and job completion** — `hooks/useInitialData.ts` via `App.tsx:58,70`. Debounce reconnect refetches; medium-term split the payload into scoped queries (this also reduces F1-style render fan-out from doc 09).

*Perf acceptance gate:* React profiler during an active render job shows no whole-tree re-render per progress frame; chapter editor with a 500+ segment chapter stays responsive while rendering; production build emits separate vendor chunks.
