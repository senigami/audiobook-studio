# Test Value Audit — Shared components — 2026-07-10

Scope: 47 test files, 400 total test cases reviewed, under
`frontend/tests/unit/components/` (recursively — `chapter/`, `forms/`, `layout/`,
`overlays/`, `progress/`, `project/`, `queue/`, `ui/`, `voices/`, plus root-level
files).

An earlier audit (`test_audit_frontend_components.md`, June 2026) covered a subset
of this area — `ProjectView*`, `RecordingGuide`, `ChapterEditor_*`, `forms/`,
`layout/`, `ui/ActionMenu`, `ui/StatusOrb`, `project/*`, `voices/VoicesTabFiles` —
and marked nearly everything REAL/keep, including several items it explicitly
called "low value" (e.g. the `ProjectLibraryFiles` trio) but kept anyway. It also
explicitly excluded `queue/` and all `PredictiveProgressBar*` files from scope.
This pass re-reads every file fresh (current contents, June audit not taken on
faith) and covers the previously-excluded `queue/` and `PredictiveProgressBar*`
files for the first time. Five sub-reviews were run in parallel by file group;
findings below are consolidated and de-duplicated.

## Summary

- 16 definite-delete candidates, 20 discuss items, out of 400 total tests reviewed (47 files).
- Overall this area is in noticeably better shape than the pattern the owner is worried about: the large majority of tests (well over 90%) exercise real interactions, state transitions, or production-plausible scenarios, and several files (ChapterList, ChapterEditor_Queue, QueueItem/QueueStats, CastingSuggestionsModal, LiveOutputTableGroup, StatusOrb) are strong examples of exactly the kind of behavior-driven testing the owner wants more of. The delete candidates cluster into three recognizable patterns worth generalizing as a pruning heuristic going forward: (1) a lone static-presence smoke test sitting right next to a stronger interaction test that already covers the same element (BrandLogo, SearchableSelect, VoiceDropzone, StatusOrb, GlobalQueueFiles, VoicesTabFiles); (2) tests that have drifted from the component they claim to test — either testing a field/behavior the component no longer reads (`ChapterList` "estimated runtime" pair) or omitting props the component now requires (`ProjectLibraryFiles`); and (3) a handful of near-vacuous assertions where the query itself already guarantees the thing being separately asserted (`ConfirmModal`'s `toBeTruthy()` after `getByLabelText`). None of the findings here rise to the severity of the fabricated-behavior bugs the June queue/progress audits caught elsewhere in the codebase — this is genuine pruning of dead weight, not a correctness emergency.
