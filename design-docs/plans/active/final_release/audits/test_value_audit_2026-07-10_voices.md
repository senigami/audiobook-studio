- `frontend/tests/unit/pages/VoiceLab/SamplesSection.test.tsx:106` — `SamplesSection > renders the SampleManager component (expand/collapse button present)` — despite the name, never clicks the button or exercises the expand/collapse toggle; only checks the button exists, which the "passes profile to SampleManager" test already implies.
- `frontend/tests/unit/pages/VoiceLab/TestSection.test.tsx:80` — `TestSection > renders the Test section label` — static presence only (`getAllByText(/Test/i).length > 0`), no interaction or branch.
- `frontend/tests/unit/pages/VoiceLab/TestSection.test.tsx:87` — `TestSection > renders the Generate test button` — static presence only; redundant with the very next test (`fires onTest when Generate test is clicked`), which already has to find this same button to click it.
- `frontend/tests/unit/pages/VoiceLab/VariantsSection.test.tsx:125` — `VariantsSection > renders the Variants section label` — static text presence, no interaction/branch.
- `frontend/tests/unit/pages/VoiceLab/VariantsSection.test.tsx:130` — `VariantsSection > renders an Add variant button` — static presence only; redundant with the following test (`fires onAddVariant when the Add variant button is clicked`), which must find the same button.
- `frontend/tests/unit/pages/Voices/components/VoiceIconControls.test.tsx:47` — `VoiceIconControls > renders the copy icon prompt button` — static presence only; the two tests below already have to locate this button to click it.
- `frontend/tests/unit/pages/Voices/components/VoiceIconControls.test.tsx:52` — `VoiceIconControls > renders the upload icon button` — static presence only; no test in this file (or elsewhere found) exercises the actual upload flow (`api.uploadVoiceIcon`, `onIconUploaded`) through this button, so this test only pins that an element exists, not that anything works.
- `frontend/tests/unit/pages/Voices/components/VoicePills.test.tsx:154` (`VoicePillRow dark theme smoke > renders without error in dark theme`) — sets `data-theme="dark"` and asserts only that a `.voice-pill-row` element exists; never asserts any dark-theme-specific style/color, so it's a render-without-crash smoke test in disguise — the theme attribute is set but never checked against anything.
- `frontend/tests/unit/pages/Voices/components/VoiceUtils.test.tsx:34` — `Voice Utils > Drawer > handles resizing` — contains **zero `expect()` calls**. - `frontend/tests/unit/pages/Voices/components/VoiceModals.test.tsx:145` — `Voice Modals > ScriptEditor > keeps custom imported base variant labels editable` — a duplicate of the test immediately above it (`keeps the variant field editable and explains voice renaming separately`) with a different string value (`"New Zealand"` vs `"Default"`). `ScriptEditor`'s variant-name `GlassInput` (`frontend/src/pages/Voices/components/ScriptEditor.tsx:62-66`) has no logic that varies by `variantName` value at all, so both tests pin the exact same always-true invariant ("this input is never disabled") — no unique branch is exercised by the second one.

## DISCUSS (borderline, needs a human call)

- `frontend/tests/unit/pages/VoiceLab/TestSection.test.tsx:105` — `renders a variant selector with the profile variant name` — mostly static presence, but it does verify dynamic `<option>` generation from fixture data (variant name interpolated into the option label). Borderline between "real" and "static-presence" per the owner's own example.
- `frontend/tests/unit/pages/VoiceLab/TestSection.test.tsx:146` — `renders the engine badge` — static presence (`getByText('XTTS v2')`), but it does depend on a real lookup (`engines.find(...).display_name`), so a regression in that lookup would be caught. Weak but not pure boilerplate.
- `frontend/tests/unit/pages/VoiceLab/VariantsSection.test.tsx:148` — `renders VariantEditor rows for each profile` — the assertion (`playButtons.length > 2`) is vague/fuzzy rather than checking that both profiles actually rendered distinct rows; it does exercise the profiles→rows mapping branch, but a bug that dropped one row while leaving >2 buttons wouldn't be caught.
- `frontend/tests/unit/pages/VoiceLab/VoiceLabPage.test.tsx:150` — `renders the phase stepper with 4 steps` — `PhaseStepper`'s 4 steps (`frontend/src/pages/VoiceLab/components/PhaseStepper.tsx:12-17`) are a hardcoded constant array, not derived from props/data, so this test mostly re-asserts a fixed literal. The companion test ("marks the Ready step as active") is where the real phase-computation logic gets exercised.
- `frontend/tests/unit/pages/VoiceLab/VoiceLabPage.test.tsx:142` — `renders the back link to /voices` — static presence of the back button; no test in the file actually clicks it to confirm navigation.
- `frontend/tests/unit/pages/VoiceLab/VoiceLabPage.test.tsx:218` — `renders section placeholders (samples, variants, test)` — `SamplesSection`/`VariantsSection`/`TestSection` are fully mocked to stub `<div>`s here, so this only confirms three mocked components are still called in the render tree — useful as a "didn't accidentally delete a section" tripwire, but it's testing wiring, not behavior.
- `frontend/tests/unit/pages/Voices/components/VoiceUtils.test.tsx:15` — `Drawer > renders when open and handles close` — does reach a real assertion (`onClose` called), but finds the close button via a fragile heuristic (`buttons.find(b => b.innerHTML.includes('svg'))`) instead of `getByRole('button', {name: 'Close'})` (the component has an accessible `aria-label="Close"`, `frontend/src/pages/Voices/components/VoiceUtils.tsx:161`). Not low-value, but worth tightening rather than deleting.
- `frontend/tests/unit/pages/Voices/components/VoiceModals.test.tsx:87` — `MoveVariantModal > renders list of speakers and handles selection via SearchableSelect` — overlaps significantly with the newer, more granular `MoveVariantSearchableSelect.test.tsx` (open-dropdown + select-option + `onSelectSpeaker` called), which covers the same interaction pattern in more detail (plus a11y/combobox-absence and keyboard filtering). This test does add one thing the other file doesn't: clicking "Move Variant" and asserting `onSubmit` fires. Possibly worth trimming the redundant selection steps here and keeping only the submit assertion, but not a clear-cut duplicate given the added coverage.

## Summary

- 11 definite-delete candidates, 8 discuss, out of ~178 total tests reviewed across 21 files.
- Overall this area is in good shape: the bulk of the suite (VoicesPage, VoiceCatalogCard, MetadataEditor, HuggingFaceDiscover, ScriptEditor, VoicePills, VoicesTabHeader, voicePhase, recordingPromptSuggester + its threshold companion) is genuine behavior/interaction testing, including two well-built regression suites for real bugs found this cycle. The delete candidates cluster almost entirely in the three newer VoiceLab section components (`SamplesSection`, `TestSection`, `VariantsSection`) and `VoiceIconControls`, which each have one or two "renders the X label / renders the Y button" tests that add nothing beyond what the adjacent interaction test in the same file already covers — a leftover pattern from scaffolding tests alongside each new component rather than a systemic problem. The one true zero-assertion test (`VoiceUtils.test.tsx`'s "handles resizing") and the one genuine duplicate pair (`VoiceModals.test.tsx`'s two ScriptEditor variant-name tests) are worth fixing regardless of the broader prune decision.
