# Test Value Audit — Backend DB — 2026-07-10

Scope: 31 files, 220 total test cases reviewed (`tests/db/*.py`).

Method: 4 parallel agents each read every test file in full plus the corresponding
`app/db/` (and where relevant `app/domain/`, `app/orchestration/`, `app/storage/`) source
it exercises, then classified every `def test_...` against the rubric in
`design-docs/specs/testing-standards.md` (VACUOUS / MOCKED-OUT / WRONG-SCENARIO / FRAGILE / REAL)
and the owner's low-value patterns. ~15 of the 31 files were previously classified in the
June 2026 audit (`test_audit_db_remainder.md`); those were re-read fresh rather than rubber-stamped.
The June audit's prior deletions (test_db_migration_extended.py, test_db_speakers_extended.py,
test_deduplication.py, and the two MOCKED-OUT tests trimmed from test_performance_metrics_storage.py)
were confirmed still gone / still applied — no regression there.

## DEFINITE delete candidates

- `tests/db/test_performance_metrics_storage.py:702` — `test_xtts_sample_uses_actual_segment_count` — name/docstring claim it tests segment-count *resolution* from timing/state, but the body passes `segment_count=7` explicitly into `record_render_sample` and just reads 7 back; the `put_job()` setup is dead code, no resolution logic is ever exercised (missing-edge-case-disguised-as-coverage).
- `tests/db/test_performance_metrics_storage.py:776` — `test_render_sample_records_explicit_model_without_db_defaulting` — trivial round-trip (write `tts_model="custom-v9"`, read back `"custom-v9"`); no defaulting code path is invoked; duplicates the `tts_model` assertion already made in `test_record_render_sample_storage`.
- `tests/db/test_performance_metrics_storage.py:868` — `test_all_warm_returns_none` — true duplicate of `test_warm_samples_excluded`; same code path (all rows below the warm threshold → filtered to empty → `None`), only the sample count/values differ.
- `tests/db/test_chapters_lifecycle.py:88` — `test_move_chapter_artifacts_to_trash_rejects_non_uuid_chapter_id` — true duplicate: `canonical_chapter_id()` rejects any non-UUID string via the same `uuid.UUID()` parse/except branch already hit by the sibling traversal test (`test_move_chapter_artifacts_to_trash_rejects_invalid_chapter_id`), and this one only asserts `success is False` with no file-preservation check — strictly weaker coverage of the identical branch.
- `tests/db/test_speaker_paths.py:63` — `test_containment_rejection_via_symlink` — the test's own comment admits it "can't make Evil look like a voice root" and just confirms the resolver "doesn't blow up"; `resolve_existing_profile_dir` returns `None` for this input regardless of the containment check (no voice.json/profile.json under the symlink), so the containment assertion is unreachable — the symlink-escape scenario is never actually exercised.
- `tests/db/test_db_lexicon.py:157` — `test_add_lexicon_entry_has_created_at` — VACUOUS/"text exists" pattern: only asserts `created_at is not None and > 0`, confirming `time.time()` was called and stored, no computed logic — this is the owner's own textbook example of a low-value test.
- `tests/db/test_db_speakers.py:51` — `test_speaker_collision_handling` — despite its name, never creates a second/colliding speaker; it calls `create_speaker("Narrator 1")` once and reads it back, duplicating the opening lines of `test_speaker_crud` with zero unique assertion about collision behavior.

## DISCUSS (borderline, needs a human call)

- `tests/db/test_performance_metrics_storage.py:673` — `test_record_render_sample_stores_load_and_pure_render_seconds` — asserts `inter_group_overhead_seconds` via the exact same arithmetic the source computes (`12.0 = (50-8)-30`); does hit a distinct branch (model_load + sum_segment both present) not covered elsewhere, but borders on self-referential math.
- `tests/db/test_db_lexicon.py:112` — `test_update_lexicon_entry_replacement_only` — `update_lexicon_entry` builds its SQL generically from `updates.items()`, so this exercises the identical code path as `test_update_lexicon_entry_word_only` with the field roles swapped; marginal incremental value.
- `tests/db/test_speaker_naming.py:24` — `test_compound_default_strips_variant` and `tests/db/test_speaker_naming.py:27` — `test_compound_non_default_strips_base` — in `app/db/speaker_naming.py::infer_speaker_name`, the `if variant_name == "Default" or suffix.strip() == variant_name: return ... else: return ...` branches return the **identical expression**, i.e. the conditional is dead code in the source itself. Both tests exercise the same (branchless) path under different scenario names. Flagging both the test duplication and the apparent dead-code/latent-bug in the source for a human look — a real behavioral divergence may have been intended here and never implemented.
- `tests/db/test_db_reconcile.py:32` — `test_reconcile_project_audio` and `tests/db/test_db_reconcile.py:60` — `test_reconcile_project_audio_not_found` — both patch `app.core.config.get_chapter_dir`, but `reconcile_project_audio` doesn't call that function — it goes through `StorageManager.resolve_chapter_asset_path` → `ProjectContext.get_chapter_dir`, an unrelated implementation. The patch is inert; the tests only pass because the real (unpatched) `get_chapter_dir` call used to seed the fixture happens to compute the same path. The rest of each test (DB state assertions, the `subprocess.run`/ffprobe mock) is real — the issue is a misleading/dead mock target, not fabricated coverage. Worth a fix (repoint the patch) rather than deletion, but flagged here since it technically doesn't test what it claims to isolate.
- `tests/db/test_state_job_guards.py:30` — `test_terminal_reset_to_preparing_not_dropped`, `tests/db/test_state_job_guards.py:59` — `test_running_to_queued_blocked`, `tests/db/test_state_job_guards.py:73` — `test_terminal_to_preparing_allowed_failed`, `tests/db/test_state_job_guards.py:78` — `test_terminal_to_preparing_allowed_cancelled`, `tests/db/test_state_job_guards.py:154` — `test_failed_to_preparing` — each is a same-branch sibling of an already-KEEP test in the same class, differing only by which literal member of `ACTIVE_STATUSES`/`TERMINAL_STATUSES` is plugged in (e.g. `queued` vs `preparing`, or `done` vs `failed` vs `cancelled`). Not obviously worthless — these do document that the guard treats every member of the status set identically, which is itself a mildly useful regression fence — but they're prime candidates for collapsing into a single `@pytest.mark.parametrize` rather than being kept as five separate near-identical functions. Flagged as DISCUSS rather than delete because parametrize-consolidation preserves the coverage while just removing the duplication; an outright deletion would be defensible too.
- `tests/db/test_segment_gc.py:206` — `test_per_project_skips_active_generation` and `tests/db/test_segment_gc.py:224` — `test_per_project_dry_run` — exercise the exact same code path as `test_skips_active_generation_chapter` / `test_dry_run_deletes_nothing` respectively, just calling the per-project function directly instead of through the global wrapper (which adds no branching logic of its own — pure delegate+aggregate). Real duplicate unless the per-project function is considered a distinct public API surface worth its own direct-call coverage.
- `tests/db/test_list_jobs_by_status.py:46` — `test_list_jobs_by_status_does_not_return_other_statuses` — asserts the same filter behavior (mixed statuses present, correct subset returned) as `test_list_jobs_by_status_returns_matching_rows`, with no unique edge case added.

## Notable KEEP (high-value tests worth calling out)

- `tests/db/test_state_job_guards.py` (the ~23 non-flagged tests) — a well-designed guard-function suite: pure functions, no unit-under-test mocking, and several genuine regression fences (e.g. `test_terminal_to_preparing_allowed_done`/`_failed` are explicitly named after a bug-guard spec section; `test_eta_projection_uses_clamped_progress` catches a real interaction bug class between the regression guard and ETA projection).
- `tests/db/test_grouped_validation.py` and `tests/db/test_segment_voice_invalidation.py` — all 6 tests are real regression guards against a "suicide cleanup" class of bug (segment audio wrongly deleted on metadata-only or no-op changes); high value, keep as-is.
- `tests/db/test_performance_metrics_storage.py::test_record_render_sample_storage` and `test_global_audiobook_speed_multiplier_is_not_persisted` — both explicitly assert that an *old, wrong* behavior is NOT true anymore, not just that the new behavior is true — a stronger regression-guard shape than most of the file.
- `tests/db/test_db_reconcile.py::test_reconcile_queue_status_does_not_reset_chapter_with_done_row` — named regression test (B3) for a `NOT EXISTS` join guard; real and non-trivial.

## Summary

- 7 definite-delete candidates, 14 discuss, out of 220 total tests reviewed.
- Overall health of `tests/db/` is strong. The June 2026 audit's cleanup held (no regressions — deleted files/tests stayed deleted), and the remainder of the suite is dominated by tests that seed real DB state, exercise unmocked business logic, and assert observable persisted outcomes or explicit "old behavior is no longer true" regressions. The definite-delete findings are concentrated in a few recognizable smells: parameter round-trips with no defaulting/computation behind them (`test_render_sample_records_explicit_model_without_db_defaulting`), a "field exists and is non-null" timestamp check (`test_add_lexicon_entry_has_created_at`), and tests whose names promise an edge case (collision, symlink containment, segment-count resolution) that the test body never actually reaches. The largest cluster of DISCUSS items (`test_state_job_guards.py`) isn't really about vacuousness — it's structural duplication that a `parametrize` refactor would resolve without losing coverage, and the `test_db_reconcile.py` DISCUSS pair is a dead-mock hygiene issue (wrong patch target) rather than fabricated coverage, both worth a human decision on remediation approach rather than outright deletion.
