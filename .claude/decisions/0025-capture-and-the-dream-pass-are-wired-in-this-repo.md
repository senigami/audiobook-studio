# OD-0025: Seat memory capture is a doctrine rule and the dream pass runs at closeout
Status: accepted        Date: 2026-08-14
Scope: `.claude/agents/_shared/crew-doctrine.md` (new "Write to your own memory store" section); `.agent/rules/session-closeout.md` (new section (a2))
Context: `memory: local` was added to all eleven seats and the global `seat-memory-load.sh` / `capture-moment.sh` hooks are wired in `~/.claude/settings.json`, both confirmed current by `grep -n resolve_token` against the installed hook and the shipped `lessons-loop/scripts/` source. Recall was therefore wired and capture was not. Audited 2026-08-14: `crew-doctrine.md` named `MEMORY.md` as a write target zero times, `session-closeout.md` never mentioned the dream pass, and no `working-memory.md` existed in either populated store. The seven memories in `abfc-ada/` and two in `abfc-reviewer/` were all hand-written at closeouts. This matches the machine-wide finding in skill-arsenal's UPGRADING 2q: capture's trigger was "notice that something meaningful happened", enforced only by a seat remembering the discipline exists, and its failure mode is silence.
Decision: "Capture is a binding doctrine rule on every seat: append candidates to `working-memory.md` in your own store as they occur, promote the ones that would change future behavior, write only the store you were dispatched under. The orchestrator runs `lessons-loop`'s five-step dream pass over `.claude/agent-memory-local/` at every session closeout, and records in each seat's `MEMORY.md` that the pass ran and when."
Consequences: The rule lives in ONE shared file, not copied per profile, so a future hire inherits it from the doctrine every profile already forwards to. The `MEMORY.md` stamp exists because the dream pass clears `working-memory.md` after Absorb by design, which makes a swept store and a never-captured store indistinguishable on disk; the stamp is the only thing that tells them apart. Promotion to `~/.claude/lessons/doctrine/` is named explicitly in the closeout step so repo-independent principles do not get filed as seat memories, which is the default drift.
Disconfirming evidence: A store still holds an empty or absent `working-memory.md` after a session with real corrections in it, which would mean the doctrine line is being read and not followed and the enforcement needs to be a hook rather than a rule.
