# OD-0021: Naming is orchestrator-owned, the method is not restated locally, and the name ledger is owner-wide
Status: accepted        Date: 2026-08-04
Scope: `.claude/agents/roster.json` (`naming` object); all seat profile identity paragraphs; `.claude/agents/roster.html` colophon; `.agent/candidate-agents/README.md` (hire-time checklist); `~/.claude/orchestration-primer/name-registry.md`

Context: This repo was awakened in July 2026 under a method where each seat named itself, framed as a ceremony. That method was abolished upstream (`awaken-orchestrator` 1.23.x, `references/naming-discipline.md`): no agent names itself, naming is ordinary inline work with no rite, the orchestrator's own name is proposed and owner-ratified, and every later hire is named by the orchestrator unilaterally and reported. The skill files update themselves on `/plugin update`; this repo's own layer did not, so seven seat profiles still read "self-chosen 2026-07-20" and the roster page still told a reader names are self-chosen — i.e. the next hire would have followed the retired method. Separately, the owner-wide name registry still listed this repo's *pre-rename* roster (Tessera, Ledger, Veronica, Plumb, Edda, Rosetta, Constance, Petra) as active, thirteen days after OD-0004 renamed all eight, so the one file that answers "is this name taken?" was wrong in both directions.

Decision: "Names in this repo are assigned by the orchestrator and reported, never chosen by the seat itself. The naming method is `~/.claude/orchestration-primer/naming-discipline.md` — point at it; do NOT restate, paraphrase, or re-derive it in this repo's own files, and do NOT restore the self-naming method from an old profile. The single ledger of which names are taken is `~/.claude/orchestration-primer/name-registry.md`; keep no in-use or retired name list anywhere in this repo. The naming charter (`axis`, `register`, `persona`, `why`) lives as data in `roster.json`."

Consequences: The eight names assigned 2026-07-20 stand — nothing here asks for a rename, and `roster.json`'s `naming.why` records honestly that they predate the axis rather than back-filling one. The registry was reconciled the same day: the eight predecessor names moved to `retired` dated 2026-07-20 (the OD-0004 date, not today's), and the eight current names were registered as `active` with that same assignment date. `Astrid@audiobook-studio` (archivist) collides with `Astrid@greenlight` (reasoning twin, structural); per the registry's own rule the collision is surfaced to the owner and not resolved either way. This repo runs no avatars in its layer and nothing in it mentions them, which is the current default; the orchestrator avatar the owner commissioned lives outside the repo and is unaffected.

Disconfirming evidence: A future hire in this repo is named by a route the pointed-at method does not sanction, showing that pointing at the method rather than restating it left it too weak to be followed — in which case the fix is a one-line imperative here, never a local copy of the method.
