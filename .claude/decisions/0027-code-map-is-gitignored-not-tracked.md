# OD-0027: code map is gitignored, not tracked — aligning with upstream map-code convention
Status: accepted        Date: 2026-08-15
Scope: `.gitignore`; `.agent/code-map/` (all 35 files, untracked in place); no OD previously covered this
Context: The installed `map-code` skill (skill-arsenal, v1.9.0) documents the code map as generated, local-only, rebuilt or refreshed per clone, and never git-tracked — gitignore the whole directory, since it is a large, churning, machine-derived index of source that is already tracked, and shipping one machine's copy in project history helps no reader. This repo's `.agent/code-map/` was found committed (35 files tracked via `git ls-files`) with no OD anywhere explaining a deliberate divergence from that guidance — an undocumented drift, not a considered exception. The map itself was also 37 commits / 28 days stale at the time this was found (see the accompanying consolidation commit), which is exactly the kind of drift a tracked-but-unmaintained copy invites: a stale committed artifact reads as more authoritative than an absent one.
Decision: Adopt the current map-code convention. `.agent/code-map/` is added to `.gitignore` and removed from git's index via `git rm -r --cached` (not deleted from disk, not a history rewrite — past commits still show the tracked map exactly as it was). Going forward the map is local-only per clone: rebuilt or refreshed by the map-code skill's own update mode, never committed.
Consequences: A fresh clone of this repo has no code map until map-code build/update mode runs — this is the intended state (a repo with no map is a repo where the skill has not run yet), not a regression. Anyone relying on `.agent/code-map/` being present in a checkout without running the skill first will need to run it. No CI or hook in this repo currently depends on the map being tracked; if one is ever added, it must build the map when absent rather than fail.
Disconfirming evidence: A future session finds a real repo-specific reason the map needs to ship in history (e.g. a downstream consumer that reads it straight from a clone with no tooling) that was never surfaced when this ruling was made — that would be new information warranting a reversal, not a reason to silently re-track it.
