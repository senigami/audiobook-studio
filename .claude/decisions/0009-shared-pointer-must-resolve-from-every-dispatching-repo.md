# OD-0009: A pointer into a shared file must resolve from every repo that dispatches the seat
Status: accepted        Date: 2026-07-29
Scope: .claude/agents/_shared/; any profile or shared-doctrine pointer crossing repo boundaries (e.g. the awaken-orchestrator primer's shared files)
Context: A profile pointing at a missing shared file degrades to a dead reference with no fallback content, and nothing warns you when that happens. This is a new convention adopted during the 2026-07-29 conventions upgrade; no verbatim sentence stating it existed yet in CLAUDE.md, crew-doctrine.md, roster.json, or any profile at time of writing — flagged rather than invented, per instructions.
Decision: "**A pointer into a shared file must resolve from every repo that dispatches the seat** — check it with `test -e` from the dispatching repo, not by reading the file where it lives, because a profile pointing at a missing shared file degrades to a dead reference with no fallback content and nothing warns you (OD-0009)." — CLAUDE.md, Orchestrator identity & mandate (Roster paragraph).
Consequences: Forbids treating "the shared file reads correctly where it lives" as verification. The failure it blocks is silent: a profile whose pointer does not resolve degrades to a dead reference with no fallback content and no warning, so the seat loses every rule the shared file held while the profile still looks complete. Adding a shared file is therefore a two-repo change whenever a sibling repo dispatches the same seat.
Disconfirming evidence: A pointer that fails a from-every-repo `test -e` check is nonetheless found to resolve correctly in practice for every dispatching repo that matters — i.e. the check catches nothing the simpler owning-repo check wouldn't have.
