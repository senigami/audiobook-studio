# OD-0021: skill-arsenal conventions upgrade — memory:local, orchestrator-owned naming, orchestrator agent entry
Status: accepted        Date: 2026-08-11
Scope: `.claude/agents/*.md` frontmatter (all persistent seats + the three generic executors); `.claude/agents/ada-orchestrator.md` (new); `.claude/agents/roster.json`; `.claude/agents/roster.html`
Context: `skill-arsenal`'s `UPGRADING.md` (release v1.0.0) documents three conventions this repo's own layer predates: native per-agent memory (`memory: local` frontmatter, §2n), orchestrator-owned naming going forward with self-chosen framing retired as historical-only (§2l), and a dispatchable `.claude/agents/` entry for the orchestrator separate from its mandate (§2p). Applied mechanically by Marius per Ada's dispatch.
Decision: (a) Every persistent seat's frontmatter carries `memory: local` — Marius, Junia, Astrid, Cecilia, Amina, Esther, Tamsin, and the three generic executors (`implementer`/`reviewer`/`runner`, newly installed from `plan-run`). (b) Naming is orchestrator-owned going forward: the orchestrator proposes, the owner ratifies the first name, every later hire is named unilaterally and reported. The seven seats named 2026-07-20 keep their names; their profiles' "self-chosen 2026-07-20" framing is corrected to "named 2026-07-20 (predates the current orchestrator-named convention, see OD-0004)" — historical fact, not a live method. `roster.html`'s colophon is updated to match. (c) The orchestrator (Ada) has her own dispatchable entry, `.claude/agents/ada-orchestrator.md` — frontmatter only (name, description, model, memory), pointing back to `CLAUDE.md`'s mandate section and `roster.json`'s `orchestrator` block as sources of truth, never duplicating them. `roster.json`'s `orchestrator` block gained `profile_agent_entry` and `memory` fields to match.
Consequences: A repo-scoped memory directory now auto-creates under each seat's dispatch (verify post-restart per UPGRADING.md §2n — frontmatter edits to already-loaded agents are cached for the rest of a session). Each profile's existing "## Memory" prose section still points at the old global path (`~/.claude/agent-memory/<slug>/MEMORY.md`) — this is a known discrepancy, flagged to Ada rather than silently resolved: whether to migrate that prose to point at the new local location, and whether any accumulated content in the old global files is worth carrying over, is the owner's/orchestrator's call, not a mechanical step of this upgrade. Do not re-open orchestrator-self-naming for the seven grandfathered seats — they are not being renamed.
Disconfirming evidence: A future session finds the old global `~/.claude/agent-memory/<slug>/MEMORY.md` files still being read anywhere in a profile's *operative* instructions (not just described historically) after this change — i.e. the discrepancy was left live rather than merely documented.

**Resolved same-day by Ada:** checked `~/.claude/agent-memory/` directly — it is confirmed cross-repo pooled (e.g. `reviewer/` holds 34 files, several clearly from unrelated repos, not audiobook-studio). Content is not cleanly separable by repo, so **no migration** — carrying it in would import other repos' lessons into this one. Instead, each of the 8 affected profiles' "## Memory" prose (`reviewer`, `amina-runtime-verifier`, `astrid-archivist`, `cecilia-user-docs-writer`, `junia-designer`, `marius-engineer`, `tamsin-reasoning-younger`, `esther-reasoning-elder`) now states plainly that `memory: local` auto-injects this repo's own `MEMORY.md`, and names the old global path as a separate, older, unmigrated pool. The old global files are left untouched (other repos may still depend on them) and are simply no longer this repo's operative memory source.
