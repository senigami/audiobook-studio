# OD-0017: This repo's orchestration layer is edited only from a session rooted in this repo
Status: accepted        Date: 2026-07-29
Scope: CLAUDE.md orchestrator section; .claude/agents/ profiles; .claude/decisions/; roster.json; roster.html
Context: A visiting session edited another repo's orchestration layer once, adding a rule to seven seat profiles in a repo whose own decision log had already answered that question differently. Another session may also be live in a given tree at any time, so a cross-repo edit risks sweeping up in-flight uncommitted work that isn't the visiting session's to touch.
Decision: "**Nobody edits this repo's orchestration layer from outside it.** This section, the seat profiles, the shared doctrine, and the decision log are changed by a session rooted **in this repo** — never by one visiting from elsewhere, however correct the change looks. A visiting session has not read this log and may add a rule the log already answered differently, and another session may be live in this tree right now. Reading this repo from elsewhere to answer a question is fine; writing to it is not. The deliverable from outside is an instruction — an upgrade step or a spawned task — not a diff (OD-0017)." — CLAUDE.md, Orchestrator identity & mandate.
Consequences: A session working outside this repo that wants to change this repo's mandate, profiles, shared doctrine, or decision log must produce an instruction (an upgrade step or a spawned task) for a session rooted here, never a direct diff.
Disconfirming evidence: An instruction handed off this way (rather than a direct cross-repo edit) is followed faithfully by the rooted session and still produces the same drift or in-flight-work collision this rule exists to prevent.
