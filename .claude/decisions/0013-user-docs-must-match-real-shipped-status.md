# OD-0013: A shipped feature with no user-facing documentation is a finding; a placeholder described as live is the same failure in the other direction
Status: accepted        Date: 2026-07-18
Scope: .claude/agents/cecilia-user-docs-writer.md; wiki/*.md; docs/handbook/; docs/user-guide/
Context: A 2026-07-18 spot-check found that parallel rendering (the shipped default), the waveform scrubber, video-sample export, and the rebuilt read-along reader were described nowhere a user would look; the Library page's only mention of a follow-along experience still described the old Review workflow the new reader replaced. In the other direction, the same page described a tagged voice as receiving scored recommendations in the Casting stage's voice suggestion panel as though live, when that feature is a placeholder the app itself marks future.
Decision: "I exist because being technically correct in the specs is not the same as being explained to the people who paid for the product — a 2026-07-18 spot-check found shipped features undocumented and a placeholder feature described as live in the same pass (OD-0013). Both directions are the same failure: the user-facing record disagreeing with what's actually true."
Consequences: Created the user-docs-writer seat (Cecilia). She verifies a feature's actual completion status against the wiki changelog and the archivist before writing it up as available or omitting it, never trusting a "shipped" claim blind in either direction.
Disconfirming evidence: A documentation gap or a live-placeholder mislabel that this seat's verification process should have caught recurs anyway despite the process being followed correctly — i.e. checking completion status against the changelog/archivist doesn't actually prevent the two-directional failure it targets.
