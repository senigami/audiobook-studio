# OD-0028: Roster renamed to Harry Potter characters
Status: accepted        Date: 2026-08-15
Scope: All 9 `.claude/agents/*.md` seat profiles, old filename → new filename: `ada-orchestrator.md`→`albus-orchestrator.md`, `reviewer.md`→`mcgonagall-reviewer.md`, `cecilia-user-docs-writer.md`→`newt-user-docs-writer.md`, `esther-reasoning-elder.md`→`fred-reasoning-elder.md`, `tamsin-reasoning-younger.md`→`george-reasoning-younger.md`, `amina-runtime-verifier.md`→`moody-runtime-verifier.md`, `junia-designer.md`→`dean-designer.md`, `astrid-archivist.md`→`percy-registrar.md`, `marius-engineer.md`→`hermione-artificer.md`; plus `.claude/agents/roster.json`, `.claude/agents/roster.html`, `CLAUDE.md`'s orchestrator section, the two moved memory directories (`abfc-ada`→`abfc-albus`, `abfc-reviewer`→`abfc-mcgonagall`), and `~/.claude/orchestration-primer/name-registry.md` (follow-up, not yet done as of this OD).
Context: Decided via an extended brainstorm session with the owner (character-to-role fit, ranked candidates against each seat's actual job description, cross-checked against real canon behavior); see the roster-rename plan (`design-docs/plans/active/roster-rename/00-overview.md`) for the locked mapping this OD documents.
Decision: "Rename the nine persistent seats — orchestrator (Ada → Albus), reviewer (generic → McGonagall), user-docs-writer (Cecilia → Newt), reasoning-elder (Esther → Fred), reasoning-younger (Tamsin → George), runtime-verifier (Amina → Moody), designer (Junia → Dean), archivist (Astrid → Percy, and the role title Archivist → Registrar), and engineer (Marius → Hermione, and the role title Engineer → Artificer) — with no change to any seat's behavior, capability, model tier, effort default, or escalation rule."
Consequences: This OD does NOT retroactively edit any prior OD that mentions the old names — OD-0003, OD-0004, OD-0007, and OD-0024 all mention "Ada" or other old names in their own historical text, and those stay exactly as written, as accurate dated history. Anyone reading an old OD after this point should understand that "Ada" there refers to the same persistent role now named Albus, without this OD needing to touch that file. This is the owner's own explicit instruction, not an inferred convention. The line is drawn the same way OD-0024 already drew it for spawn keys, by position rather than by markup: a routing/assignment/next-action position — a live decision still awaiting a seat's input, a dispatch instruction, a "do X via `<seat>`" line — takes the new name, because it points forward at the role and is wrong the moment it's read otherwise. A pure historical-attribution position — a closed decision record, a changelog entry, a "fixed by `<seat>`" comment describing something already done — takes the name that was actually in the seat at the time, and is left alone as accurate dated history, exactly as this OD leaves OD-0003/0004/0007/0024 alone above.
Disconfirming evidence: A future session finds the old names still load-bearing somewhere this OD's scope list missed (a hardcoded reference, an external tool config, a published surface) — that is a gap in Task 008's verification sweep, not grounds to reverse the rename.
