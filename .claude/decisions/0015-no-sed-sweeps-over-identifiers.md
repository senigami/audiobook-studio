# OD-0015: A mechanical sweep is re-read wherever it compares two changed things
Status: accepted        Date: 2026-07-20
Scope: .claude/agents/_shared/crew-doctrine.md "No sed sweeps over identifiers" section; any redesign or find-and-replace across identifiers
Context: A blind find-and-replace during the 2026-07-20 roster re-naming corrupted four memory files by retro-fitting new names onto events that predated them, and left stale "one of five" boundary tables that mentioned the right number of seats in one sentence while comparing the wrong set in another. Structural checks pass on exactly these errors.
Decision: "Structural checks pass on exactly the errors mechanical edits introduce — a wrong citation still names a real record and still resolves. After any find-and-replace across a token (a name, an OD/ADR number, a model tier, a version), re-read every sentence that *compares two* of the changed things, not only the sentences that mention one (OD-0015)."
Consequences: A rename or mechanical sweep is not complete when every file mentioning the old token has been updated; every sentence *comparing* two changed tokens must be re-read separately, because that class of error passes structural (link/reference) checks.
Disconfirming evidence: The re-read-every-comparing-sentence pass is performed on a series of real sweeps and never finds an error the mention-only check had not already caught — i.e. the extra pass is followed faithfully and yields nothing, meaning comparison-type errors do not actually survive the ordinary check. Note what does not count: a sweep where the pass was skipped and no error was found says nothing about the rule, only about that sweep's luck.
