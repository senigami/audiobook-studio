# 11 — Accessibility & Performance

Code-verified findings from a 2026-06-10 audit of `frontend/src`. Each item: file:line, problem, fix, acceptance. A11y items A1–A3 + A9 are release blockers (WCAG 2.2 AA). Coordinate modal/focus work with doc 10 (U2/Q2) — do each fix once.

## Accessibility

- [ ] **A1 (Critical). ConfirmModal has no dialog semantics or focus management** — `components/overlays/ConfirmModal.tsx:36-148`. Add `role="dialog" aria-modal="true" aria-labelledby="confirm-modal-title"` (id on the h3), focus first control on open, trap Tab, restore trigger focus on close (shared `useFocusTrap` hook per doc 10 U2).
- [ ] **A2 (Critical). Drawer same gaps + mouse-only resize** — `pages/Voices/components/VoiceUtils.tsx:51-155`. Dialog ARIA + focus trap/restore; `aria-label="Close"` on the X (line 142); resize handle (line 89) gets `role="separator" aria-orientation="vertical" aria-valuenow/min/max tabIndex={0}` + ArrowLeft/ArrowRight handlers.
- [ ] **A3 (Critical). Nav buttons lose their accessible name below 1100px** — `components/layout/Layout.tsx:91-137` + `theme/utilities.css:244-246` hide `.nav-label`, leaving icon-only buttons with empty names. Add `aria-label={item.label}` unconditionally.
- [ ] **A4 (High). Icon-only buttons rely on `title` or nothing** — `ConfirmModal.tsx:92-103`, `VoiceUtils.tsx:142`, `components/queue/ReorderableQueueItem.tsx:90-108` (Trash2), `pages/ChapterEditor/components/ScriptView.tsx:427-453` (Play/Generate). Add `aria-label` to all.
- [ ] **A5 (High). Drag-reorder has no keyboard path** — `ReorderableQueueItem.tsx:70-82`. Grip gets `tabIndex={0} role="button" aria-label` + ArrowUp/ArrowDown move handlers (or explicit move-up/down buttons).
- [ ] **A6 (High). No live regions** — toast container `app/App.tsx:388-437` gets `role="status" aria-live="polite" aria-atomic="true"` (container always mounted, message conditional); add a visually-hidden polite region announcing job/chapter completion.
- [ ] **A7 (High). JsonSchemaForm labels not associated** — `pages/Settings/components/JsonSchemaForm.tsx:81-180`. Stable `id={`setting-${key}`}` + `htmlFor` per field; `aria-valuetext` on range inputs.
- [ ] **A8 (Medium). StatusOrb** — `components/ui/StatusOrb.tsx:101-103`: `aria-label` on a plain div is ignored by most AT; change to `role="img"`.
- [ ] **A9 (Critical-adjacent). Global `outline: none` with no `:focus-visible` replacement** — `theme/base.css:43` + `components.css:123,230,243,258,393`. Scope removal to `:not(:focus-visible)` and add `button:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` (and equivalents for inputs/links).
- [ ] **A10 (Medium). Landmarks/headings** — `Layout.tsx:89` nav gets `aria-label="Main navigation"`; every route gets an `<h1>` (visually-hidden acceptable) — pages currently start at h2/h3.
- [ ] **A11 (Medium). `--text-muted` contrast** — `theme/tokens.css:22,25`: #64748b is ~4.1:1 on `--surface-alt` (#f1f5f9), failing AA. Darken to ~#5a6a7e or restrict to large text. Re-check after the dark palette lands (doc 07).
- [ ] **A12 (Low). `prefers-reduced-motion`** — no handling across 18 framer-motion sites. Add the global reduce-motion CSS override in `base.css` plus `useReducedMotion()` where springs are central (modals, drawer).

*A11y acceptance gate:* axe scan clean on Library, Project, Chapter Editor, Voices, Settings, Queue drawer in both themes; full keyboard walkthrough (doc 10 verification) passes with visible focus throughout.

## Performance

- [ ] **P1 (High). LiveOutputTable re-renders on every websocket frame** — `components/LiveOutputTable.tsx:150-154` subscribes to the whole audit store snapshot; `store/liveEventAuditStore.ts:26` makes a new array per frame. Fix: rAF-throttle `notify()` in the store and/or a memoized filtered selector.
- [ ] **P2 (High). Audit store allocation churn** — `liveEventAuditStore.ts:26,30,55`: full array copies per frame, full `map` per subscriber observation. Fix: ring buffer + version counter; notify at most once per animation frame. *(Also evaluate: should the audit store even run outside the dev event-stream page? Tie to doc 06's dev-route gating and the planned runtimeDebug retirement.)*
- [ ] **P3 (High). ScriptView re-renders every span per progress tick** — `pages/ChapterEditor/components/ScriptView.tsx:358-456`: inline `renderSpan`, new Set props per segment event. Fix: extract `React.memo`'d `ScriptSpan` taking per-span booleans. This is the hottest path for large chapters.
- [ ] **P4 (Medium). Audio element leaks** — `hooks/useChapterPlayback.ts:96-141,168-175`: `new Audio()` per play; `onplay/onended/onerror` never cleared in `stopPlayback`; stale-closure fallback can target the wrong instance. Fix: clear all handlers; reuse one `<audio>` element via `src` swap.
- [ ] **P5 (Medium). 250ms poll regardless of visibility** — `pages/LiveOutput/LiveOutputPage.tsx:31-32`. Replace polling with the existing store subscription; gate on `visibilitychange`.
- [ ] **P6 (Medium). Duplicate 1s clocks** — `components/queue/QueueStats.tsx:14-15` runs one interval per mounted instance and `GlobalQueue` mounts twice (route + drawer; the dead `/queue` route removal in doc 10 Q7 fixes the duplication; still lift the clock to one shared subscription).
- [ ] **P7 (Medium). Interval hygiene in useQueueSync** — `hooks/useQueueSync.ts:154-157`: verify the interval effect has a minimal stable dep array; connection-state thrash must not overlap intervals. (Related to doc 09 F3/F4 races — fix together.)
- [ ] **P8 (Low). Bundle chunking** — `frontend/vite.config.ts`: add `manualChunks` separating `framer-motion` (~90KB) and react vendor chunks.
- [ ] **P10 (Spike). Model warm-holding between renders.** (Owner request, 2026-06-11.) Reloading the TTS model for every render (e.g. regenerate after a completed job) costs the full model-load time even though batch jobs prove the engine can reuse a loaded model across segments. The TTS Server is already a long-lived subprocess, so this is a plugin-level lifecycle question, not an architecture change. Spike scope: (1) audit what XTTS does today after a job completes — does the plugin unload the model or does it stay resident; (2) if it unloads, prototype a `keep_model_loaded` plugin setting (manifest/settings-schema driven) that keeps the model resident between jobs; (3) measure memory cost and make the setting opt-in/memory-aware so only machines with headroom enable it; (4) report findings before implementation. No rewrite in a compiled language is anticipated.
- [ ] **P9 (Low). `/api/home` mega-payload refetched on every reconnect and job completion** — `hooks/useInitialData.ts` via `App.tsx:58,70`. Debounce reconnect refetches; medium-term split the payload into scoped queries (this also reduces F1-style render fan-out from doc 09).

*Perf acceptance gate:* React profiler during an active render job shows no whole-tree re-render per progress frame; chapter editor with a 500+ segment chapter stays responsive while rendering; production build emits separate vendor chunks.
